# CAN 车身控制模拟器

基于 STM32F103C8T6 的嵌入式车身控制模拟器。项目通过按键模拟车身输入，通过板载 LED 模拟灯光执行器，并使用 I2C OLED 显示当前系统状态；后续将接入 CAN、SPI Flash、蜂鸣器和 USB-CAN 分析工具。

## V0.1 已完成

- PB11 按键控制灯光状态，采用基于 `HAL_GetTick()` 的非阻塞消抖。
- PC13 板载 LED 模拟灯光执行器（低电平点亮）。
- I2C1 驱动 SSD1306 OLED，设备 7 位地址为 `0x3C`。
- OLED 首页显示 CAN 状态、灯光状态及 1 秒心跳状态。
- 使用非阻塞 1 秒心跳任务，记录 `heartbeat_count`。
- 启动自检：OLED 显示自检页，LED 快闪 3 次后进入主页面。
- 软件按 BSP / APP 分层，`main.c` 仅保留硬件初始化与主循环。

## 硬件连接

| 功能 | STM32 引脚 | 说明 |
| --- | --- | --- |
| 状态 LED | PC13 | 板载 LED，低电平点亮 |
| 灯光按键 | PB11 | 上拉输入，按下为低电平 |
| OLED SCL | PB6 | I2C1_SCL |
| OLED SDA | PB7 | I2C1_SDA |
| OLED VCC | 3.3V | 不使用 5V |
| OLED GND | GND | 与 STM32 共地 |
| CAN RX（预留） | PB8 | CAN 重映射后使用 |
| CAN TX（预留） | PB9 | CAN 重映射后使用 |

## 软件分层

```text
main.c
  └─ AppMain_Init / AppMain_Run
       ├─ app/body_control：车身状态、心跳、灯光业务逻辑
       ├─ app/ui：OLED 首页和局部刷新
       └─ bsp：按键、LED、OLED 等板级驱动
```

## 运行流程

1. CubeMX 初始化 GPIO 和 I2C1。
2. `AppMain_Init()` 完成按键、车身状态初始化和启动自检。
3. 进入主页，显示 `CAN: OFFLINE`、`LIGHT`、`HB`。
4. 短按 PB11：切换 `LIGHT: ON/OFF`，并驱动 PC13 LED。
5. 每隔 1 秒切换 OLED 上的心跳状态。

## 关键实现

### I2C OLED

I2C 空闲时 SCL/SDA 均为高电平。主机发送 Start 后，向 OLED 发送写地址 `0x78`（7 位地址 `0x3C << 1`）。控制字 `0x00` 表示后续为命令，`0x40` 表示后续为显示数据。

### 非阻塞按键消抖

程序记录原始电平最近一次变化的时间。仅当电平稳定超过 20ms，才更新稳定状态；仅在稳定状态由高变低时报告一次按下事件。

### 非阻塞心跳

每次主循环调用 `BodyControl_HeartbeatTask()`；当 `HAL_GetTick()` 的时间差达到 1000ms 时，切换心跳状态并增加计数，不使用 `HAL_Delay()` 阻塞主循环。
